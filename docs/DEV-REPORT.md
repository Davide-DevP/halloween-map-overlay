### Dropped entirely
OCR map detection (`map-detector*`, tesseract.js, node-screenshots, runtime
sharp, cron, all detector fixtures/tests), lobby manager + `api.js` + `jspow.js`
+ axios, remote map sync (`images.js` GitHub manifest, `picture-hash.js`,

markdown docs (`privacy.js`, marked, github-markdown.css), Tom Select, Font

### Added
- `src/core/map-catalog.js` — pure, no electron/fs: `buildCatalog(listing)`,
  `mergeCustomMaps`, `findClosestMapMatch(key, catalog)` (exact →
  normalized-substring → bounded Levenshtein), `nextMap`/`prevMap` with
  wrap-around, `listCreators`.
- `src/core/map-library.js` — maps root resolution
  (`app.isPackaged ? process.resourcesPath/maps : global.dirname/maps`),
  directory listing, cached catalogue, `resolve(key) → absolute path`, and the
  `get-map-catalog` / `read-map-image` / `invalidate-map-catalog` IPC.
- `src/js/maps.js` — replaces `images.js`; no network, no realm.
- `scripts/prepare-maps.js` — crop + icon rasterisation.
- `next-map` / `prev-map` hotkeys, Ctrl+1..Ctrl+4 first-run defaults.
- A Content-Security-Policy on the main window with `connect-src 'none'`, which
  makes the "no network calls" rule structurally impossible to break.

map square ≈ 0–5) scanning inward from each edge, then optionally steps just
inside a frame line if one is there. This is documented in `AGENTS.md` so the
next person does not repeat the mistake.

## 6. Known limitations and what could not be verified

- **No GUI interaction was performed.** There is no screen capture or input
  injection available here, so nothing that requires clicking or pressing keys
  was exercised: clicking a map card, the settings sliders and the live overlay
  preview, the drag-to-position mode, the hotkey capture UI, and actually
  pressing Ctrl+H / Ctrl+R / Ctrl+←→ / Ctrl+1–4. What *is* verified is that
  those hotkeys register with the OS without error, that the IPC handlers they
  fire exist, and that the same `sendMap` path works when driven from the CLI.
  Custom map **import** likewise: the catalogue half is unit tested and the
  modal renders, but no file was actually picked through the file dialog.
- **Never tested against the real game.** The always-on-top behaviour over
  *Halloween: The Game* in borderless windowed mode is inherited from the
  reference implementation, not re-validated.
- **The release workflow could not be pushed.** GitHub rejects any push that
  adds a `.github/workflows/` file unless the token has the `workflow` scope;
  the `gh` login on this machine has `gist, read:org, repo` only
  (`remote rejected … without workflow scope`, and the Contents API returns 404
  for the same reason). Granting that scope needs a browser confirmation from
  the account owner, which is not mine to do. `.github/workflows/release.yml`
  is complete and sits in the working tree, untracked. To finish:
  `gh auth refresh -h github.com -s workflow`, then
  `git add .github/workflows/release.yml && git commit -m "Add release workflow" && git push`.
  **Until then, pushing a tag does nothing** — releases must be built with
  `npm run build:win` and uploaded with `gh release create` by hand. The
  workflow itself is therefore also **untested**: no tag has been pushed, per
  instruction.
- **The auto-update path is only half-proven.** The "no releases yet" branch was
  exercised against the live repo and behaves correctly, but an actual
  download-and-install upgrade cannot be tested until a first release exists.
  The `checkForUpdates` toggle was verified to be read, not clicked.
- **`detection-fixtures/`** (8 game screenshots + a README from the owner,
  9.7 MB) is intentional — staged
  for a future auto-detect phase. It is left untouched and excluded from the
  electron-builder `files` list, so it never reaches the installer. Nothing in
  the current code reads it. Note that auto-detection is out of scope for this
  version per `SPEC.md` §3, and any implementation of it will have to be
  reconciled with the "nothing that touches the game process" rule.
- **Linux/Wayland untested.** The respawn code is ported as-is; only Windows was
  built and run.
- **No auto-update.** Deliberate (no release feed). The `update-message` toast
  is still wired up, so re-adding `electron-updater` later is a small change;
  flagged as a TODO in `AGENTS.md`.
- **Unsigned binaries.** No code-signing certificate is configured, so Windows
  SmartScreen will warn on first run of the installer.
- `npm run build` is an alias for `build:win` — there is no Linux packaging
  target configured, since only Windows artifacts were in scope.
